Frequently Asked Questions (FAQs)

Q: How do I install PHPMake?
A: Install via Composer:
composer require --dev phpmake/phpmake

Q: What runtime requirements does PHPMake have?
A: PHP 8.3+, Composer 2+, and the `ctype`, `json`, `random`, and `zip` PHP extensions.

Q: How do I create a sample build.json?
A:
php vendor/bin/phpmake --init

Q: Is the `version` in `build.json` the PHPMake package version?
A: No. It identifies the build configuration/project version and is independent of the installed PHPMake release.

Q: What is the basic structure of `build.json`?
A:
{
  "name": "Project Name",
  "description": "Project description.",
  "version": "2.0.2",
  "targets": {
    "target_name": {
      "depends": ["dependency1", "dependency2"],
      "tasks": [
        {"type": "task_type", "params": { ... }}
      ]
    }
  },
  "default_target": "default_target_name"
}

Q: How do I run a specific target?
A: Use the target name as an argument:
phpmake <target_name>

Q: What tasks are supported?
A:
- `create_directory`: Create directories (`name`)
- `delete`: Remove files/directories (`path`)
- `copy`: Copy files/directories (`source`, `dest`)
- `exec`: Run a process without a shell (`command`, optional `args`, optional `timeout`)
- `echo`: Output messages (`message`)
- `archive`: Archive/compress a file or directory (`source`, `output`)

Q: Are paths outside the project allowed?
A: No. Filesystem task paths are normalized and must resolve inside the current working directory. Absolute paths are accepted only when they remain inside that directory. `..` components are resolved and are allowed only if the final normalized path remains inside the project. Symlinked directories and Windows junction ancestors that escape the project are rejected. UNC paths outside the project, extended-length UNC paths, and Windows drive-relative paths are rejected. Destructive tasks cannot target the project root.

Q: How do I pass arguments and set a process timeout?
A: Use an `args` JSON array of scalar values and an optional numeric `timeout` in seconds (greater than 0 and at most 86400). The default timeout is 300 seconds. Arguments are passed directly; shell operators, variable expansion, and pipelines are not interpreted. Standard output and standard error are each limited to 1 MiB.

Q: How do I enable debug/verbose logging?
A: Add the `--debug` flag:
phpmake --debug

Q: How do I validate my build.json?
A:
phpmake --validate-build

Q: What does the `--diagnostics` flag do?
A: Shows system info like PHP version, OS, and loaded extensions.

Q: How do I handle circular dependencies?
A: The tool detects cycles and throws an error.

Q: Which operating systems are supported?
A: Windows, GNU/Linux, and macOS. Filesystem case handling follows the host filesystem; Windows paths are compared case-insensitively, while macOS volumes may be case-sensitive or case-insensitive.

Q: How do I create a custom task?
A:
1. Create a new class in `src/Task/Types` extending `BaseTask`.
2. Implement `runTask()`, `validateParams()`, and `getType()`.
3. Update `TaskFactory` to map the new task type.
4. Add parameter validation to `BuildValidator` and `schema/build-schema.json`.
5. Add tests for success, failure, and unsafe inputs.

Q: What does silent mode hide?
A: `--silent` suppresses normal console output. Errors remain visible on standard error (STDERR).

Q: What happens when an external process times out?
A: PHPMake attempts to terminate the process tree. Windows uses `taskkill /T`; POSIX systems use a dedicated process group when the POSIX extension is available. If process-group support is unavailable, only the direct process can be terminated.

Q: Where are logs stored?
A: By default, logs are in the project's root in `build.log`, unless `--no-log` is used. Writes and rotation are protected by a persistent `build.log.lock` file. Logs rotate at 10 MiB and keep up to 5 rotated files (`build.log.1` through `build.log.5`).

Q: Why does the build stop abruptly?
A: The tool stops on the first failed task by default. Use `--debug` for detailed error info.

Q: Can I use PHPMake in CI/CD pipelines?
A: Yes, it's designed to work with any environment supporting PHP.
